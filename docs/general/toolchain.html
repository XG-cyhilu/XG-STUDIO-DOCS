构建Build

统一使用 CMake 生成 Visual Studio 工程并构建，顶层工程通过 add_subdirectory 引入依赖：

Visual Studio projects are generated and built through CMake, with dependencies pulled in via add_subdirectory:

cmake -S . -B .build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake `
  -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build .build --config Release

add_subdirectory 引入 VCUI 时会自动给消费方加上 /std:c++17：公开头文件包含 inline 变量，标准必须传递，否则 MSVC 默认的 /std:c++14 在包含头文件时会直接报错。

Adding VCUI through add_subdirectory propagates /std:c++17 to consumers automatically: public headers use inline variables, so the standard must be propagated or MSVC's default /std:c++14 fails as soon as the header is included.

依赖管理Dependencies

  • VCUI：无第三方依赖，仅链接系统库 d2d1 dwrite dwmapi uxtheme user32 gdi32 ole32 imm32，由 VCUI::vcui 自动传递。
  • VCUI: no third-party dependencies; it links only system libraries (d2d1 dwrite dwmapi uxtheme user32 gdi32 ole32 imm32), propagated by VCUI::vcui.
  • cpploclib：通过 vcpkg 提供静态依赖（vcpkg.json 已声明）；XGDL 需要的静态 libcurl 必须启用 schannel，不需要 OpenSSL / nghttp2 / zlib。
  • cpploclib: static dependencies come from vcpkg (vcpkg.json is included); XGDL's static libcurl must be built with schannel, without OpenSSL, nghttp2 or zlib.
  • VCL：依赖以源码副本内置到 third_party/，不使用 submodule 或 find_package；顶层自行维护 vcpkg.json（至少包含 curl），子目录清单在 add_subdirectory 形态下不生效。
  • VCL: dependencies are vendored under third_party/ rather than fetched via submodules or find_package; the top level keeps its own vcpkg.json (at least curl), since sub-directory manifests do not apply under add_subdirectory.
vcpkg install --triplet x64-windows-static --overlay-ports=path/to/port

持续集成Continuous integration

cpploclib 的 CI 为 .github/workflows/windows.yml：在 windows-latest 上执行 configure → build → ctest，任一用例失败即判红，整轮约 50 秒。测试全部不出网，网络相关用例只访问 127.0.0.1。

cpploclib's CI is .github/workflows/windows.yml: configure → build → ctest on windows-latest; any failing case turns the run red, and a full round takes about 50 seconds. No test reaches the internet — network-related cases only use 127.0.0.1.

CI 刻意排除 XGDL 与 XGNET：两者都需要静态 libcurl，而 vcpkg 的 curl CMake 包在接口中带 $<LINK_ONLY:...> 依赖，会让 install(EXPORT) 在 CMake 4.x 下报非法上下文（$<LINK_ONLY:...> may only be used for linking）。这两个模块的回归在本地通过 xgdl_demo --selfcheck 与 xgnet_demo 完成。

CI deliberately excludes XGDL and XGNET: both need a static libcurl, and vcpkg's curl CMake package exposes $<LINK_ONLY:...> dependencies that make install(EXPORT) fail as an invalid context under CMake 4.x ($<LINK_ONLY:...> may only be used for linking). Those two modules are regressed locally through xgdl_demo --selfcheck and xgnet_demo.
