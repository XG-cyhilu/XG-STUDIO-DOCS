XG STUDIO works mainly in C++, Web and .NET, with Python, Go, PHP and Java for specific jobs; this page records the actual version baseline for each.

C++：17 与 20 并行C++: 17 and 20 side by side

C++ 是自绘桌面产品的主力语言。工具链固定为 Visual Studio 2022 + MSVC 14.44，它在同一套编译器里同时支持 /std:c++17 与 /std:c++20，因此两个标准可以按工程选择，不必准备两套环境。

C++ carries the self-drawn desktop products. The toolchain is fixed at Visual Studio 2022 + MSVC 14.44, which supports both /std:c++17 and /std:c++20 in one compiler, so a project can pick either standard without a second environment.

构建命令Build command

统一用 CMake 生成 Visual Studio 工程，顶层通过 add_subdirectory 引入 VCUI / cpploclib：

Visual Studio projects are generated through CMake, with VCUI / cpploclib pulled in at the top level via add_subdirectory:

cmake -S . -B .build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake `
  -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build .build --config Release

add_subdirectory 引入 VCUI 时会自动把 /std:c++17 传给消费方：它的公开头文件使用 inline 变量，若标准没传下去，MSVC 默认的 /std:c++14 会在包含头文件时直接报错。切到 C++20 的工程则显式写 /std:c++20。

Adding VCUI through add_subdirectory propagates /std:c++17 to consumers: its public headers use inline variables, so if the standard is not propagated, MSVC's default /std:c++14 fails as soon as the header is included. Projects on C++20 set /std:c++20 explicitly.

依赖来源Dependency sources

  • VCUI：无第三方依赖，只链接系统库 d2d1 dwrite dwmapi uxtheme user32 gdi32 ole32 imm32，由 VCUI::vcui 自动传递。
  • VCUI: no third-party dependencies; it links only system libraries (d2d1 dwrite dwmapi uxtheme user32 gdi32 ole32 imm32), propagated by VCUI::vcui.
  • cpploclib：静态依赖由 vcpkg 提供；XGDL 需要的静态 libcurl 必须启用 schannel，不需要 OpenSSL / nghttp2 / zlib。
  • cpploclib: static dependencies come from vcpkg; XGDL's static libcurl must use schannel, without OpenSSL, nghttp2 or zlib.
  • VCL：依赖以源码副本内置在 third_party/，不用 submodule 或 find_package；顶层自带 vcpkg.json（至少 curl）。
  • VCL: dependencies are vendored under third_party/ rather than fetched via submodules or find_package; the top level keeps its own vcpkg.json (at least curl).

持续集成Continuous integration

cpploclib 的 CI 在 windows-latest 上执行 configure → build → ctest，约 50 秒，全部用例不出网。CI 刻意排除 XGDL 与 XGNET：两者都需要静态 libcurl，而 vcpkg 的 curl 包在接口里带 $<LINK_ONLY:...>，会让 install(EXPORT) 在 CMake 4.x 下报非法上下文。

cpploclib's CI runs configure → build → ctest on windows-latest in about 50 seconds, with no network access in any case. XGDL and XGNET are excluded on purpose: both need static libcurl, and vcpkg's curl package exposes $<LINK_ONLY:...>, which makes install(EXPORT) fail as an invalid context under CMake 4.x.

跨语言共用的三条硬约定：文本文件一律 UTF-8；路径在对外接口上统一用正斜杠或平台原生形式并明确说明；任何新增第三方依赖都要先记录来源、版本与许可，再进代码。

Three conventions hold across languages: text files are always UTF-8; path APIs state clearly whether they take forward slashes or native separators; and any new third-party dependency is recorded with source, version and licence before it enters the code.
