快速开始Quick Start

本页说明文档站的目录结构、本地预览方式、新增页面步骤与发布流程。

This page covers the documentation site's layout, local preview, how to add pages and how publishing works.

纯静态Static GitHub Pages 无需构建No build step

站点结构Site structure

文档站位于 docs/ 目录，由 GitHub Pages 直接托管；没有构建管线，也没有依赖框架。

The site lives in docs/ and is served directly by GitHub Pages; there is no build pipeline and no framework dependency.

docs/
├── index.html                    # home / catalog
├── .nojekyll                     # skip Jekyll processing
├── assets/
│   ├── css/site.css              # shared styles
│   ├── js/site.js                # shell, i18n, theme, copy
│   └── img/                      # screenshots
├── projects/
│   ├── xgstudio-cpp-ui/          # index / reference / development
│   ├── xgstudio-cpp-core/        # index / reference / development
│   └── void-craft-launcher/      # index / reference / development
└── general/
    ├── quick-start.html
    ├── toolchain.html
    ├── design.html
    └── licensing.html

每个项目固定三页：index.html 是说明（项目定位、技术栈、界面），reference.html 是参考（画廊与核心机制），development.html 是开发（精确技术栈、目录结构、API、快速开始）。左侧导航为树状，点击项目节点直接进入说明页。

Each project has exactly three pages: index.html for the overview (positioning, stack, interface), reference.html for the gallery and core mechanisms, and development.html for the precise stack, layout, APIs and quick start. The sidebar is a tree, and clicking a project node opens its overview.

本地预览Local preview

git clone https://github.com/XG-cyhilu/XG-STUDIO-DOCS.git
cd XG-STUDIO-DOCS/docs
python -m http.server 8080
# open http://localhost:8080

直接双击打开 index.html 也能阅读正文，但导航脚本、语言与主题切换依赖相对路径，建议始终通过本地服务器预览。界面语言与主题会保存在浏览器的 localStorage，也可用 ?lang=en 链接直接指定英文。

Opening index.html directly still renders the content, but the navigation shell, language and theme switching rely on relative paths, so a local server is recommended. Language and theme are persisted in localStorage, and ?lang=en forces English.

新增或修改文档Adding or editing pages

  1. 放置页面：项目文档放入 docs/projects/<slug>/index|reference|development.html，通用文档放入 docs/general/<slug>.html。
  2. Place the file: project guides go to docs/projects/<slug>/index|reference|development.html; general guides to docs/general/<slug>.html.
  3. 复用页面骨架：顶层结构保持 header / layout / sidebar / main / page-toc / pager / footer 不变，只替换 <main> 内的内容；data-root 在项目目录下为 ../..，在 general/ 下为 ..，在根目录为 .。
  4. Reuse the skeleton: keep the header / layout / sidebar / main / page-toc / pager / footer structure and replace only the contents of <main>; data-root is ../.. inside a project directory, .. under general/, and . at the root.
  5. 登记导航：在 assets/js/site.js 的 NAV 数组中按分组添加一个条目（中文与英文标题），侧边栏与上下页导航会自动生成。
  6. Register navigation: add an entry with Chinese and English titles to the NAV array in assets/js/site.js; the sidebar and previous/next pager update automatically.
  7. 更新首页：如需在首页目录中出现，在 docs/index.html 的对应分区添加一张 .card。
  8. Update the home page: to list the page in the catalog, add a .card to the relevant section of docs/index.html.

双语约定Bilingual conventions

  • 正文：每段中文用 <p data-lang="zh">，英文用 <p data-lang="en">；表格单元格与短标签用同一属性的 <span> 包裹。切换语言时 CSS 会隐藏另一侧。
  • Body text: wrap Chinese in <p data-lang="zh"> and English in <p data-lang="en">; table cells and short labels use <span> with the same attribute. CSS hides the other side when switching.
  • 页面标题：<title> 同时提供 data-zh 与 data-en，脚本按当前语言更新浏览器标签标题。
  • Page title: supply both data-zh and data-en on <title>; the script updates the tab title with the active language.
  • 代码：代码与标识符不翻译，注释可按语言保留一份通用英文注释，避免两套代码块。
  • Code: never translate code or identifiers; keep comments in English so a single block serves both languages.
  • 翻译来源：上游 README 仅提供中文时（如 XGStudio-cpp-UI、XGStudio-cpp-Core），英文内容由本仓库翻译整理，并在页面注明；出现分歧以上游仓库为准。
  • Translation source: when the upstream README is Chinese-only (for example XGStudio-cpp-UI and XGStudio-cpp-Core), the English text is translated and maintained here with a note on the page; where wording differs, the upstream repository wins.

发布Publishing

GitHub Pages publishes directly from the /docs folder on main, already enabled in the repository settings. Changes go live within roughly a minute of pushing to main, at:

https://xg-cyhilu.github.io/XG-STUDIO-DOCS/

发布注意事项：

Publishing notes:

  • .nojekyll 必须保留，否则以 _ 开头的文件与目录会被 Jekyll 忽略。
  • Keep .nojekyll: without it Jekyll ignores files and folders starting with _.
  • 页面链接使用带 .html 的相对路径，不要依赖无扩展名的“干净 URL”，静态托管不会自动补全。
  • Use relative links that include .html; extension-less "clean URLs" are not resolved by static hosting.
  • 每页底部的“在 GitHub 上编辑此页”链接按当前路径自动生成，移动文件后无需手工维护。
  • The "Edit this page" link at the bottom of each page is generated from the current path, so moving files needs no manual upkeep.
  • 发布后如页面仍显示旧内容，多为浏览器或 Pages CDN 缓存，可在链接后追加查询参数强制刷新。
  • If an updated page still shows old content, it is usually browser or Pages CDN caching; append a query parameter to force a refresh.

参与贡献Contributing

文档改进通过 Issue 与 Pull Request 提交：先在 Issue 中说明问题页面与具体错误，再提交 PR 修改；涉及接口、版本号与许可的改动需引用上游仓库的依据。

Documentation improvements go through issues and pull requests: describe the affected page and the specific error in an issue, then submit a PR. Changes to interfaces, version numbers or licensing must cite the upstream repository as evidence.

写作要求：术语与各项目 README 保持一致（例如 vcui、cpploclib 等代码侧标识符不意译）；英文使用句式大小写（sentence case），不做全大写强调；一个 PR 只解决一类问题。

Writing requirements: keep terminology aligned with each project's README (code-level identifiers such as vcui and cpploclib are not translated); use sentence case in English rather than all-caps emphasis; keep each PR focused on one kind of change.
