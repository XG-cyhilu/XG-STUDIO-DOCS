XGStudio-cpp-Core

XGstudio 的 C++ 公共组件聚合库，版本 1.0.0，Apache-2.0 许可。

XGstudio's aggregate of reusable C++ component libraries. Version 1.0.0, Apache-2.0.

C++17 CMake MSVC / x64 vcpkg v1.0.0 Apache-2.0

每个子目录都是一个可以单独拿走、单独构建的库，共享同一套 Apache-2.0 许可与构建约定： C++17、MSVC /utf-8、UTF-8 BOM 源码、CMake find_package 导出。 模块之间互不依赖，既服务于 Void Craft Launcher 生态，也能直接用于任何 Windows C++17 工程。

Each subdirectory is a self-contained library that can be taken and built on its own. All of them share one set of conventions: Apache-2.0 licensing, C++17, MSVC /utf-8, UTF-8 BOM sources and CMake find_package exports. Modules do not depend on one another, so they serve the Void Craft Launcher ecosystem and any other Windows C++17 project alike.

本地目录名：仓库在本地仍位于 cpploclib，因此 CMake 开关统一使用 CPPLOCLIB_BUILD_* 前缀。上游仓库名为 XGStudio-cpp-Core。

Local directory name: the repository still lives under cpploclib locally, so CMake options keep the CPPLOCLIB_BUILD_* prefix. The upstream repository is XGStudio-cpp-Core.

构建Build

依赖统一通过 vcpkg 提供（vcpkg.json 已声明），或按各模块 README 自行准备静态依赖。XGDL 所需的静态 libcurl 必须启用 schannel，不需要 OpenSSL / nghttp2 / zlib。

Dependencies come from vcpkg (vcpkg.json is included), or can be prepared per module README. The static libcurl required by XGDL must be built with schannel; OpenSSL, nghttp2 and zlib are not needed.

vcpkg install --triplet x64-windows-static
cmake -S . -B .build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake `
  -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build .build --config Release

集成Integration

add_subdirectory(third_party/cpploclib)
target_link_libraries(YourApp PRIVATE XGDL::xgdl XGLOG::xglog XGPROC::xgproc
                                        XGCRYPTO::xgcrypto XGSECURE::xgsecure XGZIP::xgzip
                                        XGFS::xgfs XGCFG::xgcfg XGTHREAD::xgthread XGNET::xgnet
                                        XGSHELL::xgshell XGCRASH::xgcrash XGCORE::xgcore)

只链接 XGCORE::xgcore 也能获得全部已构建模块的头文件目录（它 PUBLIC 链接这些模块），适合不想逐个列出的工程；但聚合头出错时编译代价是全量的，日常仍建议按需逐个链接。

Linking only XGCORE::xgcore still brings in every built module's include directories (it links them PUBLIC), which suits projects that would rather not list them. The trade-off is that an error in the aggregate header costs a full rebuild, so per-module linking remains the default recommendation.

可以按需关闭模块，例如 -DCPPLOCLIB_BUILD_LOG=OFF、-DCPPLOCLIB_BUILD_ZIP=OFF；共 13 个开关，命名与模块一一对应（DOWNLOAD、LOG、PROC、CRYPTO、SECURE、ZIP、FS、CFG、THREAD、NET、SHELL、CRASH、CORE）。也可以只添加单个模块目录：add_subdirectory(third_party/cpploclib/modSecure)。

Modules can be switched off individually, e.g. -DCPPLOCLIB_BUILD_LOG=OFF or -DCPPLOCLIB_BUILD_ZIP=OFF; there are 13 options, one per module (DOWNLOAD, LOG, PROC, CRYPTO, SECURE, ZIP, FS, CFG, THREAD, NET, SHELL, CRASH, CORE). Adding a single directory works too: add_subdirectory(third_party/cpploclib/modSecure).

测试与持续集成Tests and CI

cmake -S . -B .build -DCPPLOCLIB_BUILD_TESTS=ON
cmake --build .build --config Release
ctest --test-dir .build -C Release --output-on-failure

每个模块对应一条 ctest（tests/<模块>/main.cpp，使用自带微型断言，不引入 gtest），共 13 条用例，覆盖配置宽松解析与绑定、原子写、日志分级与落盘、标准哈希向量、AES-GCM 篡改检测、线程池、zip 往返与路径穿越、命令行引用往返、进程输出捕获、真实 dump 落盘、HTTP 回环请求与聚合头单 TU 编译等。全部用例不出网，可在无外网 CI 上稳定运行。

Each module has one ctest entry (tests/<module>/main.cpp using built-in micro-assertions, no gtest), 13 cases in total, covering lenient parsing and binding, atomic writes, log levels and flushing, standard hash vectors, AES-GCM tamper detection, the thread pool, zip round-trips and path traversal, command-line quoting, process output capture, real dump writing, loopback HTTP and single-TU compilation of the aggregate header. No test reaches the network, so they run reliably on offline CI.

CI 工作流为 .github/workflows/windows.yml：在 windows-latest 上执行 configure → build → ctest，任一用例失败即判红，整轮约 50 秒。CI 刻意不包含 XGDL 与 XGNET：两者都需要一份静态 libcurl，而 vcpkg 的 curl CMake 包在接口中带有 $<LINK_ONLY:...> 依赖，会让 install(EXPORT) 在 CMake 4.x 下报非法上下文。它们的回归在本地完成（xgdl_demo --selfcheck 自带回环服务）。

The workflow .github/workflows/windows.yml runs configure → build → ctest on windows-latest; any failing case turns the build red, and a full round takes about 50 seconds. XGDL and XGNET are deliberately excluded from CI: both need a static libcurl, and vcpkg's curl CMake package exposes $<LINK_ONLY:...> dependencies that make install(EXPORT) fail as an invalid context under CMake 4.x. Their regression tests run locally via xgdl_demo --selfcheck, which ships its own loopback server.
