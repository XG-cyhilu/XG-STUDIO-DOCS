没有 Root 级默认值继承：每个实例一份配置，缺失时按全默认 + 启发式 gameDir 即时生成，不阻断启动。

There is no Root-level default inheritance: each instance owns its config, and when missing it is generated on the fly from defaults plus the heuristic gameDir, without blocking launch.

构建与依赖Build and dependencies

  • 依赖以源码副本内置，不用 submodule、不用 find_package；同步方式是整目录覆盖上游，再按 docs/THIRD_PARTY.md 重打本地补丁。
  • Dependencies are vendored as source copies, not submodules and not find_package; syncing means overwriting the whole upstream directory, then reapplying local patches listed in docs/THIRD_PARTY.md.
  • 顶层用 CACHE BOOL "" FORCE 关掉 VCUI_BUILD_DEMO、CPPLOCLIB_BUILD_DEMOS、CPPLOCLIB_BUILD_TESTS。
  • The top level forces off VCUI_BUILD_DEMO, CPPLOCLIB_BUILD_DEMOS and CPPLOCLIB_BUILD_TESTS via CACHE BOOL "" FORCE.
  • Lighty 只以预编译静态库参与链接：CI 或本地 cargo build --release 产出，版本固定 git rev / tag，并记录 SHA-256；不在业务工程里跑 cargo。
  • Lighty participates only as a prebuilt static library: produced by CI or a local cargo build --release, pinned to a git rev/tag with a recorded SHA-256; cargo never runs inside the app build.
  • 新增依赖必须先写进 THIRD_PARTY.md，否则 PR 不接收。
  • Any new dependency must be recorded in THIRD_PARTY.md first; otherwise the PR is rejected.
cmake -B build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" `
  -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build --config Release

编码规范Conventions

  • 源码 UTF-8 带 BOM：外部 MSVC 未加 /utf-8 时会按 936 解析而报错。
  • Sources are UTF-8 with BOM: an external MSVC without /utf-8 would parse them as codepage 936 and break.
  • 错误传递用 bool + std::string& err，异常不穿越模块边界。
  • Errors travel as bool + std::string& err; exceptions never cross module boundaries.
  • UI 层禁止直接调用 core / backend 的写接口，只能发 Intent。
  • The UI layer must not call write APIs of core / backend directly; it only dispatches Intents.
  • 每个文件带 AGPL-3.0 头与 SPDX 标识；内置依赖保留其 Apache-2.0 头，不修改。
  • Every file carries an AGPL-3.0 header with an SPDX identifier; vendored dependencies keep their Apache-2.0 headers untouched.

当前状态与边界Status and limits

  • src/ 为空，v0.1 的工程与依赖清单尚未执行；本页目录与接口是蓝图。
  • src/ is empty and the v0.1 scaffolding checklist is still open; the layout and APIs here are the blueprint.
  • 接入 Lighty 前有六项待验证：最小安装/启动入口、Java 探测归属、离线 UUID 派生、Root 写入范围、退出码透出、/MD 下的体积与符号冲突。
  • Six items must be validated before Lighty integration: minimal install/launch entry points, who owns Java detection, offline UUID derivation, the write scope inside a Root, exit-code transparency, and size/symbol conflicts under /MD.
  • 页面清单未定，v0.1 只做容器与占位页；不承诺与 PCL 的功能对等。
  • The page list is undecided and v0.1 ships containers and placeholders only; feature parity with PCL is not promised.
