Void Craft Launcher

用 C++17 与 Direct2D 自绘实现的 Minecraft Java 版启动器，AGPL-3.0 许可。

A Minecraft: Java Edition launcher written in C++17 with a self-drawn Direct2D interface. Licensed under AGPL-3.0.

C++17 Direct2D VCUI CMake AGPL-3.0

项目状态：重构中。Electron 实现已移除，C++ 代码库正在从零搭建；当前以 docs/ARCHITECTURE.md（v0.2）为施工蓝图，实施顺序为先立 UI 骨架，再接入后端。

Project status: refactoring in progress. The Electron implementation has been removed and the C++ codebase is being rebuilt from scratch. docs/ARCHITECTURE.md (v0.2) is the blueprint, and work starts with the UI skeleton before the backend is connected.

产品定位是一套面向公开发布的启动器，兼容目标为 与 PCL、官方启动器完全一致的目录结构： 任意一个标准 .minecraft 文件夹都能直接作为 Root 添加，扫到的版本立刻可启动。 启动与加载器安装交由 Rust 库 LightyLauncherLib 负责，项目自身专注于外壳、目录、元数据与界面。

The product targets public release and aims for full layout compatibility with PCL and the official launcher: any standard .minecraft folder can be added as a Root and its versions become launchable immediately. Launching and loader installation are delegated to the Rust library LightyLauncherLib; the project itself focuses on the shell, directories, metadata and UI.

特点Highlights

  • 目录即插即用：与标准 .minecraft 布局一致，PCL、官方启动器或手动整理的游戏目录均可直接添加。
  • Drop-in compatible: matching the standard .minecraft layout, so folders created by PCL, the official launcher or by hand can be added as-is.
  • 版本隔离：每个实例拥有独立配置，私有元数据放在 versions\<版本名>\.vcl\，不干扰其他启动器。
  • Version isolation: per-instance settings with private metadata in versions\<name>\.vcl\, leaving other launchers untouched.
  • 加载器支持：Fabric / Quilt 走原生 JSON 安装，Forge / NeoForge 调用官方安装器。
  • Loader support: Fabric / Quilt through native JSON installation, Forge / NeoForge through their official installers.
  • 原生渲染：Win32 + Direct2D 自绘，不依赖任何 Web 运行时。
  • Native rendering: Win32 and Direct2D throughout, with no web runtime involved.
  • 不污染游戏目录：除 versions\<name>\.vcl\ 外不写入任何额外文件；不复制 GPL 项目实现，只按公开规范实现。
  • No pollution: nothing is written outside versions\<name>\.vcl\, and no GPL project's implementation is copied — only public specifications are followed.

目录约定Directory conventions

一个 Root 对应一个标准 .minecraft；Root 的合法性判定是存在 versions\ 目录，不满足的文件夹不允许添加。

One Root is one standard .minecraft. A folder qualifies only if versions\ exists; anything else is rejected.

<Root>
├── libraries\
├── assets\indexes\ , assets\objects\
├── versions\
├── launcher_profiles.json     # Forge / NeoForge installers verify this
└── PCL\ ...                   # PCL's own data; VCL reads only

一个版本对应一个实例，版本目录内除游戏文件外还有 VCL 的私有元数据：

One version is one instance. Besides game files, the version directory holds VCL's private metadata:

<Root>\versions\<folder>\
├── <folder>.json         # the only identity source (may contain inheritsFrom)
├── <folder>.jar          # may be absent for child versions
├── mods\ config\ saves\ options.txt   # present when version isolation is enabled
└── .vcl\                  # launcher-private metadata

依赖策略Dependency strategy

依赖以源码副本进入仓库，不使用 submodule，也不使用 find_package：

Dependencies are vendored copies committed to the repository — no submodules and no find_package:

third_party/
├─ VCUI/          # copied from XG-cyhilu/XGStudio-cpp-UI
└─ cpploclib/     # copied from XG-cyhilu/XGStudio-cpp-Core
  • 保持上游目录结构：include/、src/、demo/ 与 CMakeLists.txt 原样保留，只在顶层用 CACHE FORCE 关闭 demo 与测试，便于整目录覆盖同步。
  • Keep upstream layout: include/, src/, demo/ and CMakeLists.txt stay as-is; only top-level CACHE FORCE flags disable demos and tests so the directory can be replaced wholesale.
  • 可追溯：内置版本的上游 commit、许可与每一处本地修改都记录在 docs/THIRD_PARTY.md。
  • Traceable: upstream commits, licenses and every local patch are recorded in docs/THIRD_PARTY.md.
  • 同步方式：把上游新版本整体复制覆盖，再按清单重打本地补丁，不做双向 cherry-pick；能上游化的改动优先推回上游。
  • Synchronisation: copy the new upstream release over the directory, then re-apply the documented patches; there is no two-way cherry-picking, and changes that can be upstreamed are pushed back first.

运行时：统一 /MDRuntime: uniform /MD

LightyLauncherLib 以静态库形式参与链接。选择 /MD 而非 /MT 的原因是： /MD 下 C++ 与 Rust（默认 dynamic CRT）共用同一份 ucrtbase 与 vcruntime140， 跨语言边界传递内存与句柄是安全的；/MT 会给两者各链一份静态 CRT，同一进程出现两套 CRT 全局状态 （errno、locale、FILE*），跨边界释放内存必然崩溃。

LightyLauncherLib participates as a static library. /MD is chosen over /MT because under /MD both C++ and Rust (dynamic CRT by default) share the same ucrtbase and vcruntime140, making memory and handle passing across the language boundary safe. /MT would give each side its own static CRT, producing two sets of CRT globals (errno, locale, FILE*) in one process — crossing that boundary to free memory is guaranteed to break.

配套要求：发布包必须携带 vcruntime140.dll / vcruntime140_1.dll（或检测 VC++ 运行库是否已安装）；全工程禁止局部改为 /MT，VCUI 的 VCUI_STATIC_RUNTIME 保持 OFF，Rust 侧不开启 crt-static。

Consequences: release packages must ship vcruntime140.dll / vcruntime140_1.dll (or detect an installed VC++ runtime); no part of the project may switch to /MT; VCUI keeps VCUI_STATIC_RUNTIME OFF and the Rust side must not enable crt-static.

分层Layering

UI 与业务分离：UI 只读取状态、只发出 Intent；业务层不依赖 UI，可独立以命令行方式跑通。仓库结构如下：

UI and business logic are separated: the UI only reads state and emits Intents, while the business layer does not depend on the UI and can run headless from the command line. Repository layout:

Void-Craft-Launcher--VCL/
├─ CMakeLists.txt
├─ vcpkg.json
├─ third_party/
│  ├─ VCUI/
│  └─ cpploclib/
├─ src/
│  ├─ main.cpp
│  ├─ app/            App lifecycle, window, routing, AppState
│  ├─ ui/             pages and components (read-only state, emit Intents)
│  ├─ backend/        IBackend, MockBackend, lighty (FFI wrapper)
│  └─ core/           directory / metadata / scanning / logging, UI-free
├─ docs/
│  ├─ ARCHITECTURE.md
│  └─ THIRD_PARTY.md
└─ tools/             fetch and verify the Lighty static library

后端以 IBackend 接口抽象，MockBackend 用于在 UI 阶段提供假数据，最终实现通过 lighty FFI 封装调用 Rust 库。目录、元数据、扫描与日志集中在 core/，不依赖任何 UI 类型。

The backend is abstracted behind IBackend; MockBackend supplies fake data while the UI is being built, and the real implementation calls the Rust library through the lighty FFI wrapper. Directory handling, metadata, scanning and logging live in core/ with no dependency on UI types.
