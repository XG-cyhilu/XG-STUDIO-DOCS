项目说明Project Overview

XGstudio 的 C++ 公共组件聚合库，13 个模块各自独立，版本 1.0.0，Apache-2.0 许可。

XGstudio's aggregate of C++ component libraries — 13 independent modules, version 1.0.0, Apache-2.0.

C++17 CMake MSVC / x64 vcpkg v1.0.0 Apache-2.0

这是什么What it is

这是一组面向 Windows 桌面程序的基础能力库：下载、日志、子进程、摘要、压缩、文件系统、配置、线程、 HTTP、编解码与密钥、桌面壳集成、崩溃转储，外加一个把它们收拢到一起的聚合头。 每个模块都能单独拿走、单独构建，模块之间互不依赖。

A set of foundational libraries for Windows desktop applications: download, logging, subprocesses, digests, archives, filesystem, configuration, threading, HTTP, encoding and key material, shell integration and crash dumps — plus an aggregate header tying them together. Each module can be taken and built on its own; modules do not depend on one another.

库最初为 Void Craft Launcher 提供地基，但设计上不绑定任何产品：没有 UI、没有全局单例约定， 也可以直接用在其他 Windows C++17 工程里。版本变更记录在仓库的 CHANGELOG.md。

It was built to underpin Void Craft Launcher, but is not tied to any product: there is no UI and no global singleton convention, so it works in any Windows C++17 project. Changes are recorded in the repository's CHANGELOG.md.

接口形态Interface shape

这个项目没有界面。它对使用者的呈现方式是一套统一的 C++ 约定：

This project has no user interface. What it presents to consumers is a consistent set of C++ conventions:

  • 命名空间隔离：每个模块一个命名空间（xgdl、xglog、xgcfg …），互不污染。
  • Namespaced: one namespace per module (xgdl, xglog, xgcfg …), with no cross-contamination.
  • 失败用返回值：接口以 bool 加错误字符串返回，不靠异常穿越模块边界。
  • Failures by return value: APIs return bool with an error string; exceptions never cross module boundaries.
  • 不回调，靠轮询：下载、日志、子进程、启动事件都由调用方按帧或按间隔取走，UI 不需要处理跨线程回调。
  • Polling over callbacks: download, log, subprocess and launch events are pulled by the caller per frame or interval, so the UI never handles cross-thread callbacks.
  • 路径统一 UTF-8：对外文件路径参数使用 UTF-8 字符串，只在 Win32 边界转宽字符。
  • UTF-8 paths: file path parameters are UTF-8 strings, converted to wide characters only at Win32 boundaries.

适用范围Scope

适合Suits
Windows 桌面程序的非 UI 基础层：启动器、更新器、安装器、工具链程序。The non-UI foundation of Windows desktop software: launchers, updaters, installers and tooling.
不适合Does not suit
跨平台工程；需要 UI 控件或渲染的项目；需要异步回调模型的框架型集成。Cross-platform projects; anything needing widgets or rendering; framework integration expecting callback-driven async.
依赖取向Dependency stance
只引入 libcurl 一个外部依赖，其余能力尽量落在系统 API（CNG、Win32、DWM）。Only one external dependency, libcurl; everything else stays on system APIs (CNG, Win32, DWM).
