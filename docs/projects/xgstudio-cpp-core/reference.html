机制画廊Mechanism gallery

下载：把不确定性收进一个队列Download: absorbing uncertainty into one queue

下载是本库中最重的一块。它把「大文件分块、小文件高并发、镜像回退、断点续传、校验重下、进度统计」压进一个管理器，调用方只看到入队、轮询和事件。

Download is the heaviest piece here. It folds chunked large files, highly concurrent small files, mirror fallback, resume, verify-and-restart and progress accounting into one manager; callers see only enqueue, poll and events.

xgdl::Manager dl;                       // 线程数、分块大小、重试策略在 Config 里
dl.Start();

// expectBytes 传 0 表示大小未知；expectSha1 为空表示不校验
uint32_t id = dl.Add(url, path, 0, sha1);

// UI 每 200ms 拉一次快照，内部按调用间隔算速度
xgdl::Progress p = dl.Snapshot();
// p.bytesDone / p.bytesTotal / p.bytesPerSec / p.active / p.failed

xgdl::Event ev;
while (dl.PollEvent(ev)) {              // 非阻塞，队列空返回 false
    if (ev.kind == xgdl::EventKind::Failed) Retry(ev.id);
}
dl.WaitIdle();                          // 测试与 CLI 用
if (task.size < largeThreshold) {       // 小文件：整文件一条连接
    fetchWhole(task);
} else {                                 // 大文件：按 chunkSize 切 Range
    for (auto chunk : Split(task, cfg.chunkSize)) {
        queue(chunk, /*retry=*/cfg.maxRetries);
    }
}
// 每个失败任务先换镜像再重试；校验不过则删文件、整任务重下

关键设计：接收缓冲是每任务一条环形缓冲，写满就暂停对应连接，避免慢磁盘把整个网络层拖死；分块与校验都在工作线程里完成，UI 线程只读快照。

Key design point: each task has a ring buffer; when it fills, that connection is paused so a slow disk cannot stall the whole network layer. Chunking and verification happen on worker threads, and the UI thread only reads snapshots.

日志：满了就丢，但要记账Logging: drop on overflow, but keep count

日志写线程不应该被 UI 拖慢，也不应该反过来阻塞业务。这里的策略是固定内存的环形队列：队列满时直接丢弃并累加计数，通过 Dropped() 暴露，而不是等待。

A log writer must not be slowed by the UI, nor block business code. The strategy is a fixed-memory ring queue: when full, entries are dropped and counted, exposed through Dropped(), instead of blocking.

bool Push(const Record& r) {
    if (!ring.TryPush(r)) {          // 队列满
        dropped.fetch_add(1);        // 记账，不等待、不扩容
        return false;
    }
    FlushSignal();                   // 唤醒写线程
    return true;
}

// UI 侧：拉取增量，不注册回调
xglog::Record rec;
while (xglog::UiPoll(rec)) { ui.Append(rec); }

级别过滤发生在入队前，因此 Debug 级在发布版几乎不产生成本；Fatal 会强制同步刷盘，保证崩溃前最后几条一定落盘。

Level filtering happens before enqueue, so Debug costs almost nothing in release builds. Fatal forces a synchronous flush so the last lines before a crash are always written.

配置：宽松解析与原子落盘Config: lenient parsing and atomic persistence

配置文件是用户会手改的东西，所以解析必须宽松（允许注释、尾逗号），保存必须原子（写临时文件再替换），否则一次断电就会留下半个 JSON。

Config files get edited by hand, so parsing must be lenient (comments and trailing commas allowed) and saving must be atomic (write a temporary file, then replace), or a power cut leaves half a JSON file.

xgcfg::Config cfg;
cfg.Load(L"global.json", &err);          // 宽松解析：注释 / 尾逗号

int64_t mem = cfg.GetInt("memoryMb", 4096);
cfg.Set("javaHome", xgcfg::Value("C:/Program Files/Java/jdk-17"));  // 点路径写入
cfg.Save(&err);                            // 原子写；失败保留原文件

if (cfg.Changed()) cfg.Reload();           // mtime + 大小，不读内容
std::wstring tmp = path + L".tmp";
WriteAll(tmp, Dump(root, pretty));   // 先写临时文件并 flush
MoveFileEx(tmp, path, MOVEFILE_REPLACE_EXISTING);  // 再原子替换
// 任何一步失败都保留旧文件

Binder 把结构体字段与点路径双向绑定：读取时从配置拉值到字段，写回时从字段推到配置，避免每个设置项都手写两行转换。

Binder binds struct fields to dot paths in both directions: fields are pulled from config on load and pushed back on save, so no setting needs hand-written conversion code.

压缩：先防守，再解压Archives: defend, then extract

zip 解包默认不可信：条目名可能带 ..\ 跳出目标目录。这里在写盘前做路径规范化与穿越拒绝，并对每个条目校验 CRC 与长度。

A zip archive is untrusted by default: entry names may contain ..\ to escape the target directory. Paths are normalised and traversal rejected before writing, and each entry's CRC and size are verified.

for (const Entry& e : archive.Entries()) {
    std::wstring out = Join(dest, e.name);
    if (!IsInside(dest, out)) { err = "path traversal"; return false; }
    if (!ExtractOne(e, out)) return false;     // inflate → CRC + size 校验
}
// 写入端：数据先写 .tmp，全部成功后再重命名提交
