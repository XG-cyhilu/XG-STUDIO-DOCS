快速开始Quick start

add_subdirectory(third_party/cpploclib)

target_link_libraries(YourApp PRIVATE
    XGDL::xgdl
    XGLOG::xglog
    XGCFG::xgcfg)
# 只拿一个模块：把 modCfg 目录整个拷走即可
add_subdirectory(modCfg)
target_link_libraries(YourApp PRIVATE XGCFG::xgcfg)
cmake -B .build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" `
  -DVCPKG_TARGET_TRIPLET=x64-windows-static `
  -DCPPLOCLIB_BUILD_TESTS=ON
cmake --build .build --config Release
ctest --test-dir .build -C Release --output-on-failure

测试与 CITests and CI

  • tests/ 下 12 个用例目录，每目录一个 main.cpp，共用 test_util.h 的最简断言。
  • Twelve test directories under tests/, each a single main.cpp, sharing minimal assertions from test_util.h.
  • 第 13 条是 xgdl_demo --selfcheck，以可执行文件自检代替单测，因此需要 CPPLOCLIB_BUILD_DEMOS=ON。
  • The thirteenth is xgdl_demo --selfcheck, using a binary self-check instead of a unit test, so it needs CPPLOCLIB_BUILD_DEMOS=ON.
  • 所有用例不出网：HTTP 相关逻辑通过本地假数据与解析路径覆盖。
  • No case touches the network: HTTP logic is covered through local fixtures and the parsing path.
  • CI 特意排除 XGDL 与 XGNET：vcpkg 的 curl 导出带 $<LINK_ONLY:…>，在 CMake 4.x 下会破坏 install(EXPORT)，因此在 CI 里只验证其余 11 个模块。
  • CI deliberately excludes XGDL and XGNET: vcpkg's curl export carries $<LINK_ONLY:…>, which breaks install(EXPORT) under CMake 4.x, so only the other eleven modules are verified in CI.

已知边界Known limits

  • 仅 Windows / x64；没有 POSIX 分支。
  • Windows / x64 only; there is no POSIX branch.
  • 接口以 C++ 类型暴露，不提供 C ABI；需要 FFI 时由上层自行包一层 extern "C"。
  • APIs are exposed as C++ types with no C ABI; wrap them in extern "C" when an FFI boundary is needed.
  • XGNET 为同步客户端，长连接复用与并发由调用方用线程池组合。
  • XGNET is a synchronous client; connection reuse and concurrency are combined by the caller through the thread pool.
  • XGCRASH 只写 minidump，不做符号服务器上传。
  • XGCRASH writes minidumps only and does not upload to a symbol server.
